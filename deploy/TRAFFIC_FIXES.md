CouponLeo traffic fixes, September 2026

Coupon cards now precede introductory material on store/category pages. Their first page is fetched during SSR with the selected market. The API uses bounded direct queries instead of loading the full catalog for each process; the exact-store path now supplies its required store metadata. Known expiry dates are prioritized. Listing responses suppress expired, conflicting-percentage, and repeated/banner-variant records without deleting feed data. Counts/pagination still describe source records, so some pages can contain fewer cards after quality filtering. Unknown expiry is explicitly unconfirmed and merchant-feed records are not represented as checkout-tested.

Code reveal, merchant links for offers without a code, saved-item controls, market filtering and pagination are preserved. Store advice explains conditions and redemption. Legacy homepage aliases redirect; unknown single-segment routes return 404. Partially translated navigation stays available, with English canonical URLs until full translated main content is reviewed. Localized sitemap files remain valid empty XML files. The current store sitemap excludes the sampled missing store. Google Analytics and the existing Google verification file are included.

Deployment: install cpleo-api-traffic-fixes.conf as /etc/systemd/system/cpleo-api.service.d/traffic-fixes.conf; install couponleo-ui-release.conf as /etc/systemd/system/couponleo-ui.service.d/release.conf. Build on a separate machine, verify /srv/couponleo-ui/releases/20260906-traffic-fixes on port 4174 against preview API 9601, then switch /srv/couponleo-ui/current and restart canonical services. Temporarily route Nginx to preview ports while restarting. Keep the old built UI and source backup until the release is established.

Rollback material is in /root/backups/couponleo-traffic-fix-20260906: the original Git bundle, API source, environment, systemd units, and Nginx files. Environment backups are private and must not be committed. Restore old UI service configuration and original API code/configuration together; test both services before restoring original Nginx upstreams. Do not restore only an old UI against an unverified API.

Validation before deployment: 34 frontend tests, 7 backend regression tests, production build, SSR response checks, preview mobile workflow checks. No production database rows are edited by this release. Merchant checkout validity and eventual search ranking changes require separate evidence.

The SSR route functions are registered through Analog .server.ts entry points for the English and localized home/store/category routes. Shared loader code has no Angular or SVG dependencies. Missing entity payloads remain successful data responses so Angular can render its existing not-found view and set the HTML response to 404.

All sampled pages had no horizontal overflow or browser errors. Store/category pagination and merchant-offer dialogs worked; the India store filter showed the empty state.
