CouponLeo 502 incident, September 7, 2026

The UI and API were running, but Nginx rejected the UI response with "upstream sent too big header". The upstream Server-Timing value was 5,599 bytes. Nitro production diagnostics had been enabled by build-environment defaults. Its timing plugin includes a global list of loaded-chunk timings; the header grew as more page modules were visited, including on static responses. Short checks immediately after deployment did not reproduce this later growth.

Immediate restoration: scoped Nginx UI proxy buffers were increased to 16 KiB and the diagnostic header hidden. Homepage, store, robots and favicon then returned 200. Permanent correction: ui/vite.config.ts explicitly disables Nitro debug and timing, independent of the build environment. The build was checked to exclude timing instrumentation. Existing UI features, data and API code are unchanged.

Regression check: deploy/check-response-headers.py loads public and localized page modules in one running process, then rechecks home and robots. It rejects Server-Timing on the direct UI upstream and requires response headers below Nginx's original 4 KiB limit. Run it against 127.0.0.1:4173 as well as running deploy/check-release.py against the public site. Public checks alone can miss an upstream issue when Nginx hides a header.
